# Логи и обновление интерфейса

Проверка от 23 октября 2026 года. Исходный журнал и данные входа в репозиторий
не добавлялись.

## Что в логах нормально, а что требует исправления

| Запись | Оценка и результат |
| --- | --- |
| 147 ответов `200` и один `201` | Запросы обработаны; регистрация выполнена |
| 27 ответов `204` на favicon | Штатный пустой ответ |
| 12 ответов `304` | Используется браузерный кеш; изменённые стили и скрипты имеют версию `v=6` |
| Три `401` на `/api/account` до входа | Кабинет защищён от гостевого доступа |
| 16 ответов `404` на `.well-known/...com.chrome.devtools.json` | Служебная проверка Chrome, к магазину не относится |
| 35 `Request timed out` | Обычно ожидание данных в простаивающем HTTP-соединении. Закрытие таких соединений и сброс соединения браузером теперь логируются на DEBUG |
| Пять `OperationalError: server closed the connection unexpectedly` | Реальные разрывы PostgreSQL. Пул теперь проверяет соединение перед выдачей и заменяет устаревшее; недоступность БД возвращает `503` с `Retry-After` |
| Один `ForeignKeyViolation` при удалении Т-Банка | Интеграция используется заказами. История сохраняется; показано объяснение и доступна кнопка «Отключить» |
| 11 ответов `400` на запросы СДЭК и сохранение настроек | Валидация или ошибка настройки/провайдера; по коду причину не определить. Текст ответа теперь виден в интерфейсе |
| `unknown PostgreSQL timezone: '+00:00'; will use UTC` | Предупреждение с переходом на UTC. Соединения приложения теперь явно используют UTC; SQL-файлы читаются в UTF-8 и на Windows |

Журнал приложения не объясняет, почему сам PostgreSQL закрыл соединения.
Проверка пула устраняет повторное использование оборванного подключения.
При повторяющихся `503` проверьте журнал сервера БД и доступность его адреса.
Для PostgreSQL в Docker:

```powershell
docker compose ps
docker compose logs --tail=100 postgres
```

Записи и платежи после сетевого сбоя автоматически не повторяются: транзакция
могла завершиться. Существующая защита оформления через idempotency сохранена.

## Интерфейсы

- Предоставленный логотип используется на витрине, в меню, кабинете, админке
  и клиентском сервисе. WebP с прозрачностью весит около 33 КБ.
- На телефоне меню выезжает снизу; закрытие — кнопкой по центру, снаружи или
  Escape. Фокус остаётся внутри меню и возвращается на кнопку открытия.
  Категории и помощь имеют вложенные списки на компьютере и телефоне.
- Корзина и модальные окна товара на телефоне занимают весь экран.
- Отзыв доступен из оплаченного заказа в кабинете. Сервер проверяет владельца
  и статус CONFIRMED, допускает один отзыв на заказ, включая одновременные
  отправки. До публикации администратором отзыв помечен как ожидающий модерации.
  Поля авторства и публикации от клиента игнорируются. Миграция
  `005_customer_reviews.sql` применяется автоматически при запуске.
- `/client-service` содержит все шесть разделов присланного документа с
  сохранёнными текстом и контактами. Поддержаны вкладки, клавиатура,
  ссылки `#delivery`, `#refund`, `#preorder`, `#policy`, `#public-offer`,
  `#organization`, `#cookies` и прежние адреса документов.
- Первый экран явно занимает 100% ширины. Ограничение высоты вместе с
  `aspect-ratio` больше не сжимает блок до 1400 px на широких мониторах.
- Полосы прокрутки тонкие, с прозрачной дорожкой, скруглённым ползунком
  и отдельными цветами для светлой/тёмной темы. Оформление общее для
  карточек, фильтров, корзины, кабинета и админки; прокрутка сохранена.
- Общие поля, кнопки и цвета: `ui.css`; магазин: `storefront.css`; кабинет:
  `account.css`; админка: `admin.css`. Прежние `style.css`, `shop.css`,
  `reference.css` и `admin-v2.css` больше не подключаются к этим страницам;
  файлы оставлены для ранее закешированных версий.
- Админка: единая сетка, адаптивное меню, светлая/тёмная темы с сохранением
  выбора, выровненные формы и редактор вариантов с внутренней прокруткой.
- Заказы: поиск по номеру/покупателю/треку, фильтр оплаты, состав, контакты,
  доставка и отдельная форма статуса сборки/трек-номера.
- Кабинет: обзор с реальным балансом и счётчиками, последние заказы,
  отдельные разделы заказов, бонусов и настроек. Счётчики учитывают всю
  историю; список ограничен последними 100 заказами. Детали раскрываются
  в карточке; трек-номер можно скопировать.
- Старые позиции без снимка названия получают название из каталога и сумму
  из сохранённых цены/количества. Реальные нулевые суммы после скидки
  сохраняются.
- Фильтры магазина имеют собственные списки: стрелки, Home/End, Enter,
  Escape, выделение выбора и закрытие снаружи.
- Оформление разделено на контакты, получение, оплату и итог; на телефоне
  блоки идут друг за другом. Текст согласий переносится отдельно от чекбокса.
- Город СДЭК недоступен при отключённой интеграции. Ошибка расчёта не убирает
  самовывоз; устаревший ответ не меняет новый выбор доставки.
- Галерея имеет явные области сетки без пересечений. Блоки и карточки
  появляются с анимацией; `prefers-reduced-motion` отключает движение.
  Без скрипта анимации содержимое остаётся видимым.

Темы админки и магазина сохраняются отдельно. Выбор оформления хранится
в localStorage; авторизация использует защищённые cookie.

## Обновление в Windows

После получения новой версии кода в активном `venv`:

```powershell
python -m pip install -r requirements.txt
python -m pip check
python -m store
```

В открытой вкладке нажмите `Ctrl+Shift+R`. Существующие `.env`, ключ шифрования,
базу и `var/media` сохраните.

Для старых фотографий товаров, ещё сохранённых большими base64-строками,
предусмотрена отдельная повторяемая миграция:

```powershell
python -m store.manage migrate-media
```

Она создаёт WebP-версии в `var/media` и сохраняет цены/остатки. Это важно для
быстрой загрузки каталога, обновлённого со старой версии магазина.

## Проверки

95 Python-тестов с PostgreSQL, без пропусков: принудительный обрыв отдельного
соединения, восстановление пула, `503`, защита связанных заказов, изоляция
клиентов, состав исторических заказов и проверка отзывов после оплаты.

В Chromium проверены регистрация, профиль, корзина, промокоды, пагинация,
редактирование товаров/фото/отзывов, лояльность, темы, заказы, клавиатура и
адаптивная вёрстка, отправка и публикация клиентского отзыва, вложенное меню
и все разделы клиентского сервиса на ширинах 320–1440 px.
Тестовые данные и имитация банка работают в отдельной
временной схеме PostgreSQL, которая удаляется после проверки.
Реальные платежи и запросы с пользовательскими ключами СДЭК не выполнялись.
