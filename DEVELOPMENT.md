# Разработка магазина

Нужны Python 3.12 и PostgreSQL 16. Используйте существующий checkout: облачная
задача уже изолирована, отдельный worktree не требуется. Все SQL-миграции
применяются автоматически один раз, под advisory lock, при старте приложения.
Перед обновлением существующего магазина сохраните резервную копию базы.

```bash
docker compose up -d --wait postgres
python3 -m venv venv
venv/bin/python -m pip install -r requirements.txt
cp .env.example .env  # Только если .env ещё нет; существующий не перезаписывать.
# Укажите в .env собственные ADMIN_PASSWORD и STORE_MASTER_KEY.
venv/bin/python -m store
```

В подготовленной облачной среде уже есть private `.env` и Python в
`/workspace/.apex-environment/venv`. Заново создавать их не требуется.
Не меняйте мастер-ключ после сохранения секретов интеграций без миграции.

## Что добавлено

- `/account`: регистрация, вход, профиль, смена пароля с отзывом сессий,
  заказы и история баллов. Пароль хешируется PBKDF2 с солью; в БД сохраняется
  SHA-256 токена сессии, cookie — HttpOnly/SameSite. Email нормализуется.
- Промокоды на конкретный product_id: проценты/рубли, срок, лимит применений,
  включение/отключение, редактирование. Проверка и скидка выполняются сервером.
- Лояльность: по умолчанию 5% начисления и до 20% списания после промокода.
  Проценты меняются в админ-панели. Доставка не приносит баллы. Гости не получают
  баллы задним числом: войдите до оформления. Email чека берётся из аккаунта.
- Баллы и товар резервируются транзакционно до оплаты, повторная попытка с тем
  же idempotency_key не создаёт повторного списания. Подписанное уведомление
  CONFIRMED проверяет сумму и начисляет один раз. Полная отмена/возврат
  компенсирует баллы, промокод и остатки. Старые NEW после CONFIRMED игнорируются.
- Админ-панель: страницы и поиск каталога, создание размеров пачкой, отдельная
  загрузка фото, редактирование категорий/отзывов/промокодов/интеграций,
  этапы сборки и трек-номер заказов. Статус оплаты вручную не меняется.
- RabbitMQ подготовлен отдельно и не используется: [план](RABBITMQ.md).

Email-подтверждение и восстановление забытого пароля через письма потребуют
почтового провайдера; сейчас есть смена пароля из кабинета с проверкой текущего.
При неопределённом исходе Init банка резервы не снимаются по таймеру: оплату
нужно сверить с банком. Частичные возвраты должны пройти отдельную сверку
позиций/баллов; их нельзя трактовать как полный возврат. План фонового
reconciliation описан в RABBITMQ.md. Это ограничения платёжного процесса,
которые нужно закрыть перед включением реального эквайринга.

## Производительность и фотографии

Витрина получает 24 кратких карточки, админ — 40. Полный товар с фотографиями и
описанием загружается при открытии. Поиск/фильтры выполняются в БД для всего
каталога. Запросы админ-панели параллельны; отзывы/интеграции/заказы загружаются
при открытии раздела. PostgreSQL соединения берутся из пула (1–8), а не создаются
для каждого запроса. Публичный каталог кешируется на 5 секунд и сбрасывается
после изменений; личные данные и админские API имеют `Cache-Control: no-store`.
Ответы сжимаются gzip, статические файлы поддерживают ETag/304.

Новые фото сохраняются как WebP с адресом по SHA-256 в `var/media/`, создаются
версии 240/480/960 px. JSON содержит URL, а не base64. Статические изображения
витрины уменьшены с 12 682 118 до 665 352 байт. Изображения референса добавляют
1 167 044 байта с ленивой загрузкой, Barlow хранится локально (47 064 байта).
Тяжёлые секции отложены; нет запросов к Google Fonts, Tilda или
finishlinefever.com для открытия сайта. Поддерживается reduced motion.

Для **уже сохранённых** base64-фото один раз выполните:

```bash
venv/bin/python -m store.manage migrate-media
```

Команда повторяема, обрабатывает товары по одному и не меняет цены/остатки.
В production сохраняйте `var/media` на постоянном томе и резервируйте вместе
с БД; в Docker образе это должен быть bind mount/volume. Можно задать абсолютный
`STORE_MEDIA_ROOT` переменной процесса. Не очищайте эту папку при деплое.

Это по-прежнему монолит на stdlib ThreadingHTTPServer. Для публичного трафика
нужны обратный прокси с TLS/лимитами/кешем файлов и наблюдение за latency/ошибками.
Встраиваемый limiter различает адреса соединений; за общим proxy необходимо
применять ограничения на edge по реальному IP, а настройки приложения проверить
на реальной топологии. Результаты локального теста не заменяют нагрузочный
тест публичного адреса, VPN и сетей покупателей.

## СДЭК

В интеграциях задайте ID/Secret, среду, коды города/офиса отправителя, тариф,
вес и габариты. Ключи хранятся зашифрованными. Включение выполняет реальную
проверку OAuth и калькулятора перед сохранением. Поля secret можно оставлять
пустыми при редактировании: другие сохранённые секреты не пропадают.

Реализованы OAuth с кешем по конфигурации, однократное обновление после 401,
таймауты и понятные ошибки, поиск городов через backend API СДЭК, ПВЗ по коду
города/индексу, наценка/страховка/бесплатный порог, округление мм вверх до см,
габариты варианта × количество, сроки с учётом подготовки. При оформлении
ПВЗ сверяется с ответом СДЭК, цена доставки вычисляется повторно на сервере.
Сохранённая настройка офиса предназначена для будущей отгрузки; создание
накладных и отслеживание через API ещё не подключены. Сейчас трек вводит админ.

Для реальной проверки нужны разрешённые `api.edu.cdek.ru`, `api.cdek.ru` и
действующие настройки интеграции. На момент разработки интеграций в базе нет;
сетевые вызовы проверены через имитацию ответов API, без утверждения о
проверке действующего договора СДЭК.

Сайт-референс finishlinefever.com при повторной проверке доступен. Перенесены
компоновка главной, оформление карточек/галереи/корзины, мобильное меню,
изображения и шрифты. Источники и адаптация описаны в [DESIGN_REFERENCE.md](DESIGN_REFERENCE.md).

## Проверки

Из корня checkout загрузите локальную конфигурацию в процесс тестов. Тесты БД
создают отдельную случайную схему и удаляют только её; таблицы магазина не трогают.

```bash
APEX_TEST_DATABASE=1 venv/bin/python - <<'PY'
from dotenv import load_dotenv
import sys, unittest
load_dotenv('.env')
result = unittest.TextTestRunner(verbosity=2).run(unittest.defaultTestLoader.discover('tests'))
sys.exit(not result.wasSuccessful())
PY
venv/bin/python -m compileall -q store tests
node --check store/presentation/static/script.js
node --check store/presentation/static/admin.js
node --check store/presentation/static/account.js
```

Без `APEX_TEST_DATABASE=1` проверки PostgreSQL явно пропускаются. Для сверки
контрактов СДЭК не используются реальные ключи или создание отправлений.
